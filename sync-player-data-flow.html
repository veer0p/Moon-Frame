Moon-Frame Video Sync Architecture

This document visualizes how video playback (play, pause, seek, rate changes) stays synchronized across multiple clients in real-time using Supabase Broadcasts.

Data Flow Breakdown

1. Local Action Triggered

User interacts with the VideoPlayer.jsx (e.g., clicks play). The local DOM element updates, and a sync function (syncPlay, syncSeek) from useVideoSync.js is called.

2. Room State Update

The sync function calls updateRoom() provided by useRoom.js. This function packages the new state (e.g., { is_playing: true, video_time: 12.5 }) and assigns last_action_by: username.

3. Dispatch & Broadcast

updateRoom() simultaneously saves to the Supabase Postgres DB (if logged in) and fires a high-speed Realtime Broadcast message over the room-<roomCode> channel. Local React state is updated instantly.

4. Remote Client Receives

Other clients' useRoom.js hook is subscribed to the Broadcast channel. They receive the event and update their local roomState object in React.

5. Applying Remote State

The useEffect inside useVideoSync.js watches roomState. It checks roomState.last_action_by !== username to ignore echo events. If remote, it applies changes to the DOM videoRef.current.

6. Drift Correction (Seek)

If the time difference between the local video and the remote state is greater than 1.0 second, a hard seek (video.currentTime = roomState.video_time) is enforced to snap them back into sync.
